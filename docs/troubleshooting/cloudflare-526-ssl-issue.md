# Cloudflare 526 SSL Certificate Issue - Troubleshooting Context

## Problem Summary

**Error:** Cloudflare returns error 526 - "Invalid SSL certificate"
**Domain:** `grafana.jeremymr.dev` (and other `*.jeremymr.dev` subdomains)
**Origin Server:** Envoy Gateway at `192.168.0.241:443`

## Current State

### What's Working
- ✅ `homelab-cert` secret exists with valid Let's Encrypt certificate
- ✅ Certificate has correct SANs: `*.ghost.jeremymr.dev`, `*.jeremymr.dev`, `jeremymr.dev`
- ✅ Certificate issued by: `C=US, O=Let's Encrypt, CN=R13`
- ✅ Gateway references the secrets with correct namespace
- ✅ Gateway status shows `ResolvedRefs: True`
- ✅ ArgoCD has synced the Gateway configuration

### What's NOT Working
- ❌ Envoy is serving a certificate from `allocation-ca` (not Let's Encrypt)
- ❌ The `allocation-ca` certificate has no subject and Cloudflare cannot validate it

### 2. Gateway Configuration (Fixed)
File: `manifests/infra/envoy-gateway/gateway.yaml`

```yaml
listeners:
  - name: https
    protocol: HTTPS
    port: 443
    tls:
      mode: Terminate
      certificateRefs:
        - name: homelab-cert
          namespace: envoy-gateway-system  # <-- This was missing, now added
        - name: saima-cert
          namespace: envoy-gateway-system
```

**Fix Applied:** Added explicit `namespace: envoy-gateway-system` to `homelab-cert` reference.

### 4. Direct Connection Test (Shows the Problem)

# Expected output (CORRECT):

```

### 5. Cert-Manager Logs - Important Discovery
```
I0314 15:50:09.973309 ... "Certificate must be re-issued" ... reason="DoesNotExist" message="Issuing certificate as Secret does not exist"
```

**Finding:** The certificate secrets were DELETED at 15:50:09 and had to be re-issued. This may have caused a timing/sync issue with Envoy Gateway.

### 6. `allocation-ca` Source (Mystery)

The `allocation-ca` certificate is NOT found in:
- Any Kubernetes secret in any namespace
- Envoy container filesystem
- Envoy config dump
- Crossplane certificates (which use `CN=Crossplane`)
- Envoy auto-generated secrets (`envoy`, `envoy-gateway` which use `CN=envoy-gateway`)

**Hypothesis:** `allocation-ca` appears to be a fallback/default certificate generated by Envoy Gateway when:
1. It cannot find or load the referenced TLS secrets
2. SNI matching fails
3. There's a timing issue between secret creation and Envoy configuration

### Step 1: Restart Envoy Gateway Controller
The Envoy Gateway controller may have cached the old configuration or missed the secret updates.
```bash

```

### Step 2: Restart Envoy Proxy Pods
Force the proxy pods to re-read the configuration.
```bash
kubectl rollout restart deployment -n envoy-gateway-system -l gateway.envoyproxy.io/owning-gateway-name=prod-web
```

### Step 3: Verify Certificate
After pods are ready:
```bash
echo | openssl s_client -connect 192.168.0.241:443 -servername grafana.jeremymr.dev 2>/dev/null | openssl x509 -noout -issuer -subject
```

### Step 4: If Still Failing - Check Envoy xDS
```bash
kubectl exec -n envoy-gateway-system $(kubectl get pods -n envoy-gateway-system -l gateway.envoyproxy.io/owning-gateway-name=prod-web -o jsonpath='{.items[0].metadata.name}') -c envoy -- curl -s localhost:9901/config_dump
```

```bash
kubectl get envoyproxy -A -o yaml
```

If none exists, consider creating one to control certificate behavior.
